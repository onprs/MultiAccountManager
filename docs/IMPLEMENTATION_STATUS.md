# 实现状态与功能范围

本文档汇总当前代码库的功能实现、架构设计、后续规划及运维考量。

## 功能实现

### 运行时与进程管理

- **技术栈基准**：Next.js 16 App Router、React 19、Node.js 24.22.1、pnpm 11.13.1 与 PostgreSQL 14+。
- **进程编排**：由轻量级 supervisor 统一管理 Web 进程与 `pg-boss` Worker，支持 POSIX 信号转发、优雅关停、独立降权运行 UID 与心跳保活。
- **配置与生命周期**：支持无数据库状态启动、存活探针（`/api/health/live`）与就绪探针（`/api/health/ready`）、基于 AEAD 的加密运行时配置（`runtime.enc`）及发布清单 SHA256 校验。
- **数据库迁移**：内置递增迁移管理（`0000` 至 `0007`），迁移过程应用全局咨询锁（PostgreSQL advisory lock）、版本校验和比对与 Schema 完整性检查。
- **部署脚本集**：提供 1Panel 部署准备、运行时状态校验、域名/RP ID 重新配置与 Sub2API 连接预配工具。

### 身份认证与安全引导

- **初始化流程**：Setup 向导验证初始化令牌（恒定时间比对、有效期管理、单会话控制与限流），并校验 PostgreSQL 版本、权限、连接池预算及 TLS 模式。
- **通行密钥（Passkey）**：基于 WebAuthn 规范实现首位管理员免密注册、条件式免密登录、多凭据重命名、敏感操作会话提权以及防误删保护（保留至少一个有效凭据）。
- **身份迁移**：支持具备备份确认的域名与 RP ID 重配流程，撤销旧会话与旧来源凭据，并平滑引导管理员重新注册。

### 浏览器端零知识保险库

- **内存隔离模型**：加解密计算与 TOTP 生成在独立的同源 Crypto Worker 线程中执行。主密码与派生根密钥仅存在于 Worker 内存空间，保险库锁定或离开页面时自动销毁。
- **加密方案**：采用 Argon2id 密钥派生、XChaCha20-Poly1305 认证加密、记录绑定相关数据（AAD）与版本化密文信封。
- **生命周期操作**：支持主密码或恢复密钥解锁、空闲超时自动锁定、手动锁定、主密码更新重新封装及恢复套件离线确认。
- **数据交互契约**：服务端 API 仅处理密文信封与非敏感元数据，通过版本并发锁（revision lock）保证更新一致性。明文数据仅在用户交互展示或剪贴板操作时按需解密。

### 账号与凭据管理

- **记录管理**：支持多属性账号记录的端到端加密增删改查、逻辑归档、批量状态变更、分页及非敏感元数据过滤。
- **盲索引检索**：支持基于 HMAC-SHA256 的邮箱精确盲索引查找，兼顾加密隐私与快速检索。
- **TOTP 令牌**：支持标准 `otpauth://totp` URI、Base32 密钥及二维码图片解析，具备倒计时刷新、时间步长偏差校正及凭据展示。
- **批量导入**：提供 2FAuth（schema-1 JSON）与 OpenRouter 导出文件的纯浏览器端解析与批量加密入库。
- **平台恢复码**：支持批量规范化、盲索引去重、独立加密存储、通行密钥提权查看及状态流转。

### Sub2API 服务集成

- **双域密钥隔离**：外部集成凭据与用户保险库彼此独立，集成令牌使用独立服务密钥环与连接绑定 AAD 加密。
- **连接规范**：通过 HTTPS 建立安全通信，基于最小权限原则（`account_observer:read account_observer:delete`）进行鉴权与健康诊断。
- **数据同步**：支持远端目录分页拉取、唯一邮箱自动关联、手动绑定、配额快照采集及状态变化跟踪。
- **异常协同与清理**：提供账号健康度标准化、状态异常检测、告警去重与确认，以及跨平台账号级联删除的幂等重试机制。

### 质量与测试覆盖

- **静态与安全检查**：接入 ESLint、TypeScript 严格模式、代码格式化检查与 npm 高风险依赖审计。
- **单元与集成测试**：覆盖客户端密码学、解析器、迁移脚本、Better Auth 鉴权逻辑、账号领域服务及 Sub2API 客户端。
- **端到端浏览器测试**：覆盖桌面与移动端 Worker 通信、初始化向导、Chromium 虚拟认证器通行密钥注册与登录、保险库工作区及恢复码流程。
- **运行时冒烟测试**：CI 环境自动验证完整构建产物的进程拉起、心跳健康、优雅停止与信号退出。

## 后续演进规划

- **条码识别增强**：为 ZXing 图片识别补充确定性生成的二维码测试夹具。
- **级联删除演练**：使用专用低权限令牌完成关联账号跨端删除的端到端演练。
- **恢复码标签界面**：完善恢复码批量标签的管理界面（底层存储与 API 已就绪）。
- **外部事件通知**：在现有站内告警基础上，评估并接入 Webhook 或即时通讯通知通道。
- **基准性能评测**：结合具体账号体量与连接规模，建立连接池预算模型与性能基线。

## 运维要点与考量

- **数据库暴露限制**：生产 PostgreSQL 端口建议限定于私有网络或容器内网访问。
- **多重备份策略**：定期执行 `runtime.enc` 与 PostgreSQL 异地备份，离线恢复套件与主配置密钥建议采用物理介质分离保存。
- **集成服务权限**：Sub2API Observer 凭据分配遵循最小权限原则，并在关联测试中优先使用测试实例。
- **规格与容量规划**：结合实际管理的账号数量与并发需求，合理调配 supervisor 进程内存与数据库连接池参数。
